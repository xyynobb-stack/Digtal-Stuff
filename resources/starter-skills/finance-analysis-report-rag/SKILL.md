# 财务分析报告

本 Skill 生成的是数据标注业务的项目经济性估算，服务于经营决策，不得改写成正式财务报表、会计核算、审计或税务报告。

## 执行前必须读取

生成任何章节前，必须完整读取 [财务分析报告大纲与文档契约](references/document-contract.md)。该文件是章节顺序、资料来源、计算口径、表格结构和每节写作内容的唯一依据；不能使用通用“财务分析报告”模板替代。

## 证据与计算边界

- 内部资料 A–F 只从 `default.my_skill_kb` 检索；返回的 `collection` 必须是 `my_skill_kb`。
- 外部资料 G 仅在大纲要求时联网检索，并标明来源和时间；无法取得时标记待补充，不得用模型常识编造行业单价或成本。
- 禁止索取或输出完整财务报表、工资明细、税务数据、银行流水和应收账龄表；回款与现金流只能写“需财务补充”。
- 成本侧只允许使用一个“人天综合成本（元/人天，含社保口径）”。拿不到实际值时才能使用可靠外部行业区间的中位数，并明确标为估算。
- 每个金额必须标明实际值/估算值、品类、时间段、公式和资料来源。无法给出推算过程的数字删除，禁止编造金额。

## 检索与章节工作流

1. 依据文档契约的 A–G 资料目录，为当前章节生成证据查询。查询必须指明客户/项目、标注品类、时间范围和所需字段。
2. 使用 Execute Code 和当前 `sys.executable` 运行 `scripts/rag_client.py`；先执行 `--check-config`，再用多个 `--query` 参数批量检索。不得调用 PATH 中不确定的系统 Python，也不得现场安装依赖。
3. 调用 `analysis_report_workflow(action="start", report_type="finance", retrieval_collection="my_skill_kb", ...)`。
4. 严格按大纲规定的计算顺序逐节生成并记录：`第0章 → 2.1 → 2.2 → 2.3 → 第1章 → 第3章 → 第4章 → 第5章`。最终 Word 仍按展示顺序排列为第0、1、2、3、4、5章。
5. 每节提示词固定包含四块：角色与任务、该节输入证据、文档契约中该节的“输出形态 + 写什么”、质量约束。禁止只给章节标题让模型自由发挥。
6. 资料不足时按契约规定的替代来源补检，最多两轮；仍不足就在对应单元格写“需财务提供/资料缺失”，不能省略章节、表格或口径声明。
7. `finalize` 成功后按文档契约生成 `.docx`。聊天框只返回简短完成说明和文件路径，不能用 Markdown 摘要代替 Word 报告。

检索实现复用市场报告的受控客户端；配置和真实 Schema 见 `market-report-rag/references/configuration.md`。
