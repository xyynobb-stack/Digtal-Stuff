# 人力资源分析报告

本 Skill 生成的是“交付视角的人力资产与产能分析”，回答团队能接什么活、能接多少、瓶颈在哪里；不得改写成 HR 部门口径的人事、绩效或薪酬报告。

## 执行前必须读取

生成任何章节前，必须完整读取 [人力资源报告大纲与文档契约](references/document-contract.md)。该文件是章节顺序、资料来源、表格结构和每节写作内容的唯一依据；不能用通用报告结构替代，也不能省略资料不足时仍要求保留的表格或声明。

## 证据边界

- 内部资料 A–G 只从 `default.my_skill_kb` 检索；返回的 `collection` 必须是 `my_skill_kb`。
- 外部资料 H 仅在章节明确要求时联网检索；无法联网或没有可靠来源时标记“资料缺失”，不得用模型常识冒充证据。
- 禁止检索或输出个人薪酬明细、绩效结果、劳动合同、社保公积金和离职面谈记录；成本位置统一写“需 HR 提供口径”。
- 分析对象只能是岗位、技能和流程。人员统一使用工号，不做个人产量排名，不写“某人不行”之类评价。
- 所有数字必须带品类、时间段和计算口径；无法由证据或公式支持的数字删除，不得估造。

## 检索与章节工作流

1. 依据文档契约的 A–H 资料目录，为当前章节生成证据查询。查询必须包含资料类型、品类/岗位、项目或时间范围，不能只把用户原问题原样送入 RAG。
2. 使用 Execute Code 和当前 `sys.executable` 运行 `scripts/rag_client.py`；先执行 `--check-config`，再用多个 `--query` 参数批量检索。不得调用 PATH 中不确定的系统 Python，也不得现场安装依赖。
3. 调用 `analysis_report_workflow(action="start", report_type="hr", retrieval_collection="my_skill_kb", ...)`。
4. 严格按大纲顺序逐节生成并记录：`0.1 → 0.2 → 0.3 → 1.1 → 1.2 → 2.1 → 2.2 → 第3章 → 第4章`。0.3 生成后必须作为 1.1、1.2 的固定人效基线；0.2 必须带入第3章识别单点依赖。
5. 每节提示词固定包含四块：角色与任务、该节输入证据、文档契约中该节的“输出形态 + 写什么”、质量约束。禁止只给章节标题让模型自由发挥。
6. 资料不足时根据契约规定的替代来源补检，最多两轮；仍不足就在对应单元格写“资料缺失/需补充”，不能删掉章节或改换结构。
7. `finalize` 成功后按文档契约生成 `.docx`。聊天框只返回简短完成说明和文件路径，不能用 Markdown 摘要代替 Word 报告。

检索实现复用市场报告的受控客户端；配置和真实 Schema 见 `market-report-rag/references/configuration.md`。
